How to export Tempo worklogs to CSV

You may want Tempo's worklogs in a file for a backup, for billing in a spreadsheet, or to move to another app. Tempo's Logged Time report has a raw data export that gives one row per worklog. This page gives the steps, the permission that decides whose time is in the file, and what the columns mean.

I checked these steps on 2026-11-03 with "Timesheets by Tempo - Jira Time Tracking" on a Jira Cloud test site. Tempo changes its screens often, so a menu name may have moved since.

Before you export: make sure everyone is in the file

Tempo exports only the worklogs you are allowed to view in Tempo. Being a Jira administrator does not give you that, and the export does not warn about the rows it leaves out.

  1. Open Tempo, then Settings, then Permission Roles.
  2. Choose Add permission role and tick View Worklogs.
  3. Add yourself under Add users, keep Role access on All resources, and save.

After exporting, compare the people in the file with the people you expect.

Export the raw data

  1. In Jira, open Tempo from the Apps menu, then Reports.
  2. Under Logged Time, choose Create Report, then Create. The grouping does not matter for the export.
  3. Set the date range at the top left to cover the history you want, and press Apply.
  4. Press Export at the top right and choose Download Raw Data.
  5. In "Select export option", press the CSV icon (the third icon). "Include Approval Status" can be on or off.

Tempo saves a file named like Report_01_Oct_26_30_Nov_26_Raw_Data_Logged_Time.csv. The file is UTF-8 with commas. The XLS and XLSX icons give Excel files instead.

Tip: keep the original CSV. If you open it in Excel and save it again, Excel may rewrite the dates and number formats.

What the columns mean

Column names below are from the export I took on 2026-11-03. Tempo renames columns from time to time and by Jira language (Tempo, https://www.tempo.io/product-news/changes-to-logged-time-report-raw-data-export), so yours may differ. Atlassian now calls issues "work items" and projects "spaces", and the export follows that.

Column What it holds
Work Item Key, Work Item summary The Jira issue the time was logged on
Logged Hours, Logged Seconds The time spent. Seconds is exact; hours is rounded
Work date The date and the start time, for example 2026-10-20 10:00
User Account ID, Full name The person who logged the time in Tempo
Work Description The worklog's description. A worklog without one is exported as "Working on work item KEY-1"
Billable Hours, Billable Seconds The billable part of the time
Account Key, Account Name, and other Account columns The Tempo account the time was logged against
Tempo Team, Team Lead ID The person's Tempo team
Space Key, Space Name The Jira project
Work Item Type, Work Item Status, Epic, Parent Key, Component, Version Name Fields of the issue at export time
Work Item Original Estimate, Work Item Remaining Estimate (hours and seconds) The issue's estimates at export time
One column per work attribute, named after it (for example "Work type") The value of each Tempo work attribute
Approval status Only when "Include Approval Status" is on
Date created, Date updated When the worklog was created and last changed
Tempo Worklog ID Tempo's own ID for the worklog

What is in Jira and what is only in this file

Tempo writes each worklog into Jira as well, with the same issue, date, start time and duration. In Jira, though, the author is the Tempo app ("Timesheets by Tempo - Jira Time Tracking") and the comment is "time-tracking". The real author, the description, the account and the work attributes stay in Tempo. Source: Tempo, https://help.tempo.io/kb/latest/why-do-we-see-timesheets-as-the-worklog-author What that breaks, and the options: why Jira shows "Timesheets by Tempo" as the worklog author.

So the hours survive in Jira without Tempo, but who logged them, whether they were billable and for which account are only in Tempo and in this export.

See your export as weekly timesheets

The Tempo data preview reads the CSV in your browser and shows it the way Saguaro Hours for Jira shows timesheets: one week per screen, a row per issue, a column per day, per person. The file is not uploaded.

Import it into Saguaro Hours

The admin page of Saguaro Hours imports this exact CSV. It matches each row to its Jira worklog by issue, date, duration and start time, and stores next to it the billable flag, the account name, up to five work attributes and the real author. Reports, approvals, the dashboard gadget and the weekly totals then count those hours for the person who logged them, marked "from Tempo". In Jira itself the Tempo app stays the author, because the app never edits Jira worklogs. A check against Jira runs first and writes nothing, and running the same file twice changes nothing new.

On my test site, a report grouped by person for 20 October to 3 November gave 16.83 h and 4 h, 20.83 h in total, the same as Tempo's own Logged Time report for that range. Step by step: Moving from Tempo.
