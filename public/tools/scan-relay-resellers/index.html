Scan Relay for copier dealers and IT providers

What it does

Scan Relay is a small Windows service you install on any always-on PC at the client's office. The copier sends scan-to-email the way it always has, to that PC on port 25, 587 or 2525, with any username and password. Scan Relay sends each scan on to Microsoft 365 with Microsoft's modern sign-in (OAuth, through Microsoft Graph). No firmware update, no static IP, no connector, no DNS changes.

  • Works with any copier or scanner that can scan to email over SMTP.
  • Signs in once with the mailbox scans should come from; the copier never holds a Microsoft password again.
  • Queues scans on disk if the internet drops, and sends them when it's back.
  • Sends scans up to about 3 MB per email, the most Microsoft accepts with the Mail.Send permission. Set each copier's maximum email size, or "split email by size", to 3 MB (2 MB if a scan still fails) so long jobs arrive as several emails. Larger single emails need an option that isn't released yet.
  • Accepts mail only from the office's local network.
  • Tells you when something breaks: it emails an address you choose, posts to a webhook (Teams, Slack, your PSA) and writes to the Windows event log, so a scan that can't be delivered or a sign-in that needs renewing reaches you before the client calls.

Rolling it out with your RMM tool

The same ScanRelay.exe installs without any prompts when you run it as SYSTEM or administrator:

ScanRelay.exe install --quiet --license KEY --alert-email noc@yourmsp.com --webhook https://...
  • --port 25|587|2525 picks the copier port, and --accept-tls takes SSL/TLS from copiers that won't send without it.
  • Running it again updates the program in place and keeps the client's settings and sign-in. Only the options you pass change.
  • ScanRelay.exe status prints whether scans are getting through and exits 0 (working), 1 (warning), 2 (not working) or 3 (service not running), for an RMM check.
  • Event log source ScanRelay, with fixed event IDs: 10 sign-in needs renewing, 20 a scan couldn't be delivered, 30 scans waiting too long, 40 can't listen for copiers, 51 trial ended, 1 working again.
  • ScanRelay.exe uninstall --quiet --purge removes it and its data.

The one step you can't script is signing in to Microsoft 365: someone signs in with the scanner mailbox in a browser on that PC, over your remote access tool, and a Microsoft 365 admin approves Scan Relay once per tenant.

Which clients are affected?

Paste your client domains into the Microsoft 365 domain checker: it shows which ones are on Microsoft 365 and gives you a CSV. In those tenants, the SMTP AUTH clients report (Exchange admin center, Reports, Mail flow) lists every device still signing in with a password.

Setting up a client

  1. On an office PC that stays on, download and run Scan Relay. It installs itself as a Windows service and opens its setup page.
  2. Sign in with the Microsoft 365 mailbox scans should come from. The first time at each company, a Microsoft 365 admin approves it once ("Consent on behalf of your organization").
  3. On the copier, set the SMTP server to that PC's address (shown on the setup page), port 25, any username and password, no SSL. Set its maximum email size, or "split email by size", to 3 MB.
  4. Send a test scan, then enter one of your license keys on the setup page (or pass it with --license at install).

If the copier still has SSL/TLS turned on from when it sent to smtp.office365.com, Scan Relay's log says so and tells you what to change.

Questions dealers ask

  • Why not just enable OAuth on the copier? Do that wherever the model supports it. Scan Relay is for the many units that can't, or whose firmware update isn't worth the visit.
  • Why not a Microsoft 365 connector or direct send? Connectors need a static public IP and admin work; direct send only reaches the client's own mailboxes. Scan Relay delivers anywhere, from a normal office connection.
  • Is client data sent to you? No. Scans go from the office PC straight to Microsoft 365. Scan Relay only contacts my server to check a license key. The details for your clients' IT people, checked against the code: how Scan Relay handles your mail.
  • Windows warns that the app is unrecognised. It's new; click More info, then Run anyway.
