Reports and exports

Reports is a tab on the Saguaro Hours page, open to every user.

Run a report

  1. Choose a range: this week, last week, this month, last month or custom.
  2. Optional filters: team, users, projects, projects to exclude, and a JQL filter.
  3. Group by one field, then optionally by a second: user, team, project, epic or parent, issue, issue type, label, billable, any attribute, or a Jira field (see below).
  4. Optional: add Jira fields as extra columns of the detail table and the Detail CSV and Excel exports.
  5. The screen shows totals per group, a grand total and a detail table.

Regrouping after the report has loaded is instant, except to a Jira field the last run did not read: the screen then asks you to run the report again.

On a short screen (a 1366 x 768 laptop, for example) the filters fold into one line after a run, so the results start near the top. The line says what the report holds (range, team, people, projects, JQL, grouping) and keeps Run report and the exports. Show filters opens them again; Hide filters folds them on any screen.

Filters

  • Projects: only these projects. Exclude projects: every project but these, so a site with 50 projects does not need 49 picked.
  • JQL filter: only issues that match a JQL query you type, for example component = Billing AND labels != internal or the query of a saved Jira filter. Check asks Jira whether the query is valid and shows Jira's message if not. The report runs it the same way before it reads anything. An ORDER BY at the end is ignored. The query is added to the report's own conditions (the date range and the filters above), so it can narrow a report but never widen it. Brackets and quotes must be balanced.
  • Only issues over estimate: keeps the issues whose time logged (by everyone, all time) is above their original estimate. It needs no new run and applies to the screen and every export.
  • Every filter runs as you, so Jira's permissions decide what you see.

Jira fields

Group by and Extra detail columns list the Jira fields of your site that make sense as groups: select lists (single, multiple, radio, cascading), text, number, user pickers, labels-style fields, components, fix and affects versions, priority, status, resolution, sprint, assignee, reporter and creator, custom fields included. Dates, time tracking fields and rich text system fields are not listed.

  • A field with several values (components, a multi-select, sprints) is grouped under one combined value, like labels, so totals never double count.
  • Issues without a value are grouped under "Not set".
  • The values are read in the same Jira search that finds the issues, so a field adds no extra calls.
  • Up to 10 extra columns. They appear after the attribute columns and before Description. Reports without them export exactly the same columns as before.

A long run shows how far it has got, an estimate of the time left once a few seconds have been timed, and a Cancel button. Cancel shows nothing from that run. The estimate is rough: a Jira rate limit wait or one very long issue moves it.

What counts

  • Hours are native Jira worklogs, read as you. You see worklogs on issues you can browse.
  • Days are bucketed in your Jira time zone.
  • A worklog with several labels, or a person in several teams, is placed under one combined label. Totals do not double count.
  • The screen shows the first 500 detail rows. Exports include all rows, up to the 25,000 limit.
  • A report holds up to 25,000 worklogs. Above that it stops and shows no totals, because partial totals would be wrong for billing. Narrow the date range, or filter by team, user, project or JQL, and run it again.
  • If the billable and attribute data cannot be read, the screen warns you instead of showing everything as not billable.

Estimate versus logged

Grouped by issue, epic or parent, or project, the summary adds Jira's own time tracking figures:

  • Estimate: the original estimate. Remaining: the remaining estimate. Logged all time: the time logged on the issue in Jira by everyone, at any date.
  • Hours in range: what the report counted (your range and filters), next to Logged all time.
  • % used: Logged all time on the issues that have an original estimate, as a share of that estimate. Over 100% is highlighted.
  • An issue over its estimate is tagged "Over estimate"; a group says how many of its issues are. Detail rows carry the same tag.
  • Each issue counts once in a group, however many people logged on it. An issue's own figures are used (Jira's, without its sub-tasks or, for an epic, its child issues), and a group adds up the issues in the report, that is the issues with worklogs in the range. An epic's own estimate counts only if work was logged on the epic itself.
  • An issue without an estimate shows blanks, not zero, and is never over.
  • Summary CSV and Excel gain Original estimate, Remaining estimate, Logged all time, % of estimate used and Issues over estimate columns for these groupings, and the Hours column is called "Hours in range". Other groupings export exactly as before.
  • The figures are read in the same Jira search that finds the issues, so they add no calls.

Cost and revenue

Jira administrators set hourly rates on the admin page (Rates). Until any rate is set, reports show hours only, with a note saying where rates are added (no columns of $0.00). Once a rate is set, reports add money to the hours, for people allowed to see it:

  • Cost: every hour at the person's cost rate on the worklog's day. A person's own cost rate comes first, then the default cost rate.
  • Revenue: billable hours only, at the billing rate on the worklog's day. The rate of the worklog's value of the chosen attribute (for example Account = Client A) comes first, then its project's rate, then the default billing rate.
  • Each rate starts on a day (or "from the start") and lasts until the next one. A rate change prices later work at the new rate and keeps earlier work at the old rate, so past months still add up the same.
  • An hour with no rate on its day shows no amount, rather than a guess.
  • The summary gains Cost and Revenue columns, grouped and sub-grouped like the hours, with totals. The detail table gains Cost and Revenue per worklog (the tooltip shows hours x rate). Summary CSV and Excel gain "Cost (USD)" and "Revenue (USD)" columns (in the site's currency); Detail CSV and Excel gain the cost rate, cost, billing rate and revenue of each worklog.

Who sees money: Jira administrators, and the people an administrator lists under "Who can see money" on the admin page. Team leads are not added on their own, as approving time is a different job from seeing what it costs. Everyone else gets the same reports without any money column; the app never sends rates to them. A person who may see money still only sees it for worklogs Jira lets them see.

Billing summary

With money shown, Billing summary (next to the exports) turns the report into a one-page summary per project, or per value of an attribute such as Account: hours, billable hours, billing rate and amount (billable hours x rate), with a total. A rate change inside the range gives two lines for that project, one per rate, so each line can be checked by hand. You can change the title.

  • Print opens your browser's print dialog with only the summary on the page, in dark text on white whatever your Jira theme. Choose "Save as PDF" there for a PDF.
  • Download for printing (.html) saves the same summary as a file you can open and print from your browser.
  • Billable hours with no billing rate are counted in the hours and named in a warning, and add nothing to the amount.
  • The summary uses the report's range and filters: run the report for the client's period first. It is not an invoice: there is no invoice number, tax or accounting sync.

Saved reports

  • Save the current setup under a name. You can keep up to 50.
  • Saved reports belong to you. Load, Update and Delete (with confirmation) are available.
  • A preset range such as This week moves forward when you load it. A custom range stays fixed.
  • The JQL filter, excluded projects, Jira field grouping, extra columns and the over-estimate filter are saved with the report. Reports saved before these options existed load as they were, with the new options empty.

Exports

  • Summary CSV.
  • Detail CSV.
  • Excel (.xlsx) with Summary and Detail sheets.
  • Billing summary, printable (see above), for people allowed to see money.

CSV files use UTF-8 with a byte order mark and CRLF line ends. Text that starts with =, +, - or @ gets a leading quote so a worklog description cannot run as a spreadsheet formula. The files are built in your browser and are not sent anywhere.

Limits

  • Up to 25,000 worklogs per report.
  • If Jira keeps refusing with a rate limit after 90 seconds of waiting on one call, the report stops with a message and no table. It never shows part of the hours.

Measured in our load test, on 300 issues with one person's worklogs and one viewer:

  • A report of 4,644 worklogs took 15 to 18 seconds.

Estimates, not measured. No report near 25,000 worklogs has been run. These figures are extrapolated from that load test of 5,970 worklogs, as about 4 ms per issue to search, 31 ms per issue to read and 1.1 ms per worklog for billable flags:

25,000 worklogs spread over Estimated time
1,600 issues 1.5 minutes
5,000 issues 3.5 minutes
25,000 issues 15 minutes, and likely to meet Jira's rate limits

Time depends mostly on the number of issues. Many people, several viewers at once and very large sites have not been measured.

At 5 worklogs per person per working day, 25,000 is about 238 people for a month, 79 for a quarter and 19 for a year. These are arithmetic, not measurements. Larger ranges need a filter or a shorter range.
